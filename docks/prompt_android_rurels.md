# Android デプロイ時の実装ルール（通知まわり）

あなたは優秀な Android / React Native エンジニアです。
本ドキュメントは、`mock/` で検証した仕様を **Android アプリとしてデプロイ・ビルドする際**に必ず守る実装ルールです。
`docks/development_flow.md` の【ステップ 2】以降、および `docks/prompt_android.md` に沿った移植作業時に適用してください。

---

## 1. 適用タイミング

* **対象:** `androi/` への移植、開発ビルド、本番向け APK/AAB など、**スマホ本体にインストールする Android アプリ化**の段階
* **対象外:** `mock/` を Expo Go で動かす段階（Expo Go SDK 53+ では本体通知 API が制限されるため、モックではアプリ内 Alert 代替を許容する）

---

## 2. 通知の実装ルール（必須）

### 賞味期限アラート等のユーザー向け通知

* **禁止:** デプロイ済み Android アプリにおいて、賞味期限アラートなどの「端末通知として見せるべき案内」を、アプリ内の `Alert.alert()`（または同等のダイアログ）だけで済ませること
* **必須:** スマホ本体の**システム通知**（通知シェード / ステータスバーに出るローカル通知）で届けること
* 実装手段の例: `expo-notifications`（開発ビルドまたはスタンドアロンビルド）、または Android ネイティブの Notification API / WorkManager 等
* 通知許可（Android 13+ の `POST_NOTIFICATIONS` 等）を適切にリクエストし、拒否時は設定画面への誘導などフォールバック UX を用意すること
* チャンネル（Notification Channel）を定義し、重要度・表示名を要件に合わせて設定すること

### モックとの差分の扱い

* `mock/` 側に Alert ベースのデモ通知が残っていてもよい
* `androi/`（または prebuild 後の実機ビルド）では、**Alert 代替を本番挙動にしない**こと。移植時にシステム通知へ置き換えること

---

## 3. AI（あなた）への指示

1. Android アプリ化・移植の作業では、本ファイルの通知ルールを必ず確認し、Alert のまま残さないこと
2. 通知まわりの変更を提案・実装するときは、「システム通知であること」「許可・チャンネル設定を含むこと」を明示すること
3. モック段階で Alert を使っている理由（Expo Go 制限）を、Android 化の言い訳にして本体通知を省略しないこと

---

以上を、`androi/` 移植およびデプロイ作業の必須ルールとして扱うこと。
